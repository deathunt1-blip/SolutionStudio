# Phase 1 验证记录

版本：v0.3.0。验证环境：Windows、本地 PGlite、Node.js，2026-09-24。

## 自动回归与构建

完整回归覆盖既有 Knowledge、分类、Refinement、Feishu、结构化参数、去重，以及新增项目与方案模块。解密相关测试显式使用 bundled Python，不因运行时路径缺失跳过。

完整回归：33 个测试文件、371 项测试全部通过。随后补充光学口径选择页面及两类数值校验边界，共新增 5 项回归；相关 4 个文件的 87 项测试全部通过，`npm run build` 通过。

新增测试覆盖以下风险：

- 项目资料、片段、原件与资产的归属隔离；全局资料检索不包含项目私有内容。
- SceneLab 1.0 真实协议映射、数量与单位、空值、修订号、ZIP 路径与体积、PNG 完整性。
- 分组保留报告的镜头焦距、光圈、水平和垂直视场角、仿真最大距离与相机归属；旧导入数据一次升级，保留原包、原图 ID 与旧方案快照。
- 客户要求和理论能力分离，人工修正与新增输入的版本保护；人工删除的要求不在重建时恢复。
- 五类合成场景：普通实验室、大空间无人机、机器人、小空间高精度、参数不完整。使用 Mock Provider 检查工作流，不将其描述为五个真实客户项目。
- 最多三章并行且每章独立上下文，逐请求事务预留；章节失败隔离、重试、人工正文覆盖确认、过期快照、并发提交、服务中断和持久费用预留。
- 默认使用 K3 / `max` 推理强度，提供三档推理强度及显式 K2.6 选择；历史任务保留原模型与温度展示。
- 默认关闭生成限额、显式启用后的 Token / 预算控件，以及旧任务没有开关字段时继续显示原预算。
- 章节上下文大小与主资料检索、精确产品型号匹配；风格来源不能作参数依据。
- 数值的指标、单位、型号和优先级，客户要求不能冒充能力；人工修改的参数表仍接受校验。
- 报告仿真光学参数和通用产品规格分别校验；用户选择报告配置后保留差异和来源，不把仿真距离当作产品实测能力。镜头焦距、定位精度、追踪距离、场地长度分别处理。
- DOCX XML、关系、标题层级、目录字段、图表、页眉页脚与 A4 输出。

## 真实本机验收

使用用户提供的一份真实 SceneLab 报告和已有企业知识进行 Kimi 真实生成，不另外虚构客户验收指标。封面使用用户指定公司全称。私有报告、正文、图片、模型响应和导出只保存在本机，不提交 Git。

升级前停止服务并备份整个数据目录；执行迁移后，逐记录比较原有 226 份资料的标题、有效版本、状态和分类，以及 845 条结构化参数，均保持不变。数据结构从迁移 1–6 升级至 1–8。

真实验收发现并修复了以下问题：

- 早期 Kimi K2.6 验收发现非思考模式要求温度固定 0.6；显式使用该模型时仍保留此约束。
- 模型断言允许对正文作等义表述；引用 ID 仍需属于实际上下文，正文另行独立校验。
- 阈值占比的字段名带 `Mm`，不能因此把百分比单位设为毫米；工程导入现先识别百分比字段。
- 带逐项单位的三维尺寸不应拆成三个独立精度数值；文件名中的修订编号不应当作产品型号。
- 补充知识来源标题，明确历史方案和标准条款的适用边界，避免迁移为当前项目能力。
- 生成默认关闭人工 Token 与金额限制，以内容质量和依据完整性为先，不用表单内保留的数值限制默认生成。

当前新生成已改为默认 K3，独立于旧分类模型设置；始终思考，`reasoningEffort` 默认 `max`，可选 `low` / `high` / `max`。K3 使用 1M 总窗口和 131,072 token 默认输出上限，为输出与消息封装保留空间后，输入按 916,480 UTF-8 字节保守计数，单次请求超时为 600 秒。温度由模型固定为 `1`，Provider 不发送该参数。K2.6 仍可显式选择，使用其原有 256K / 32,768 / 228,352 参数和 180 秒超时。切换默认模型不改写已有任务或旧验收快照，也不代表旧模型的真实验收结果可以直接视为 K3 验收结果。

纠正项目数据时重建上下文并创建新方案快照；旧验收草稿保留并标记过期，没有直接改写旧快照。真实模型失败、重试与服务重启均保留已有正文和费用预留。

新生成任务默认 `config.limitsEnabled=false`，不会因保留在配置表单里的 3,000 输出 Token、12,000 上下文值、10 元任务预算或 250 元累计预留而停止。显式设置 `true` 后才启用自设 Token、任务预算和累计预留限制；旧任务没有开关字段时保留原有限模式解释。模型技术上限、引用和事实约束持续生效。

项目 AI 提取也独立默认使用 K3 / `max`；接口顶层 `limitsEnabled` 默认 `false`，按 916,480 UTF-8 字节窗口分批处理全部可提取项目文档与文本，每批输出上限 131,072 token、请求超时 600 秒；SceneLab 工程输入继续由 Adapter 处理。显式传入 `model: "kimi-k2.6"` 时采用旧模型对应参数。显式启用额度限制时保留原有前 12 来源单批、24,000 字节输入、4,000 token 输出和 25 元累计额度。默认不把前 12 份来源或前 24,000 字节当作全部项目材料；每批仍严格核对证据并按所选模型费率记录用量与三次尝试预留。

费用按本任务模型响应 token 和该模型单价估算，并单列保守预留，不查询共享账户余额。章节生成的预留按实际组装输入字节上界计算：`3 × ((输入字节上界 + 1024) × 模型输入单价 + 有效输出上限 × 模型输出单价) / 1,000,000`，涵盖最多三次 Provider 尝试，不再按配置的整个输入窗口一律预留，也不把 K2.6 单价用于 K3。关闭限额仍记录费用与预留，失败和中断仍保留记录；响应估算不是供应商扣费账单。模型参数依据见 [Kimi K3 官方指南](https://platform.kimi.com/docs/guide/kimi-k3-quickstart)和 [Kimi K2.6 官方指南](https://platform.kimi.com/docs/guide/kimi-k2-6-quickstart)。

K3 保守估算按每百万 token 输入 `20 + 20 = 40` 元、输出 `100` 元计算：输入包含未缓存输入与一次 5 分钟缓存写入，因此预留公式为 `3 × ((输入字节上界 + 1024) × 40 + 有效输出上限 × 100) / 1,000,000`。K2.6 仍按输入 `6.5`、输出 `27` 元估算。该口径也用于响应 token 的本地费用估算，不尝试还原实际缓存命中或供应商账单。官方单价见 [Kimi 定价](https://platform.kimi.com/docs/pricing/chat)。

## 验收边界

规则校验不能证明所有自然语言技术陈述正确，也不能替代工程实测。客户指标尚未提供的部分仍是待确认项。只有一份真实报告进入此次本机验收，其余场景是自动化测试夹具。

DOCX 结构测试不能替代排版程序逐页检查。已尝试 bundled 文档渲染流程，但该 Windows 运行时缺少 LibreOffice，尚未完成逐页 PNG 视觉验收；未调用用户桌面软件替代。Word 打开后的分页、字体替代和目录页码仍需实际检查、更新。
