# Phase 0.1 — 人工确认难例评测（2026-09-22）

本轮已完成 38 份真实资料的两组 Kimi 分类对比。**结果揭示了错误自动通过，尚不支持进入下一产品阶段。** 这批全部来自此前需人工复核的资料，具有明确选择偏差；以下比例只描述这 38 份难例，不能作为整个资料库的准确率或误放行发生率。

## 数据与可比性

- 资料库有 41 份核心字段明确由用户确认的记录；审计均存在匹配的 `user_edit`，当前均为单一版本。保留原先的 3 份在评测集外作参考样例，其余 38 份作为本轮标准答案。
- 只复用人工确认的文档类型和 Authority，保存原审计时间及本地账户标识；不把自动标签当标准答案，也不将 `local-user` 声称为已验证的个人身份。应用、主题和产品未完整人工标注，因此没有这些字段的语义 Precision/Recall。
- SHA-256 核对原文件与当前版本。另按当前自动分类类型轮流抽取 12 份自动通过资料，组成 50 份待完善清单；这 12 份尚无独立人工答案，未参与本轮计分。混合样本也不等于随机抽样。
- 两组使用相同清单、冻结标签、词表、上下文、程序摘要、`kimi-k2.6`、temperature=0.6、max_tokens=3000，每份每组一次；唯一实验开关为是否使用确认样例。
- 独立临时数据库，排除整个 50 份清单的文档 ID 和内容哈希对应样例。剩余 3 个参考样例；有样例组实际有 38/38 份召回样例。不能外推为任意样例池都同样有效。
- 每组均为 16 success、22 partial、0 failed；partial 含格式/样式未识别等解析警告，不等于整份不可读，但仍有证据遗漏风险。

## 已核查的错误机制

1. **引用标准误当作本文件权威依据。** `doc_001`、`doc_005` 的人工答案为 `standard/reference`。无样例组的 AI 权威证据未通过校验，随后却回退为规则给出的 `authoritative/0.87`。离线检查原文前 10k 字，规则唯一命中来自“规范性引用文件”里的 GB/T 编号，没有本文件正式发布、批准或发布机构标记。来源是分类规则及证据失败回退的组合，不是评测误算。
2. **实际门槛为 0.60。** `reviewThreshold=0.60` 决定是否通过；`autoAcceptThreshold=0.85` 当前只产生提示。无样例组 `doc_012`、`doc_014` 的错误 `style_only` 判断置信度恰好为 0.60，仍会通过。
3. **原文里有引文，不代表引文证明分类。** 模板、培训、内部使用等线索被模型用来推导 `style_only`，与人工用途判断不一致。`technical_knowledge/manual`、`other/contract_or_requirement` 也存在边界分歧；需要明确正反例，而不能仅根据文件名下结论。
4. **人工掌握的来源信息可能超出文件指纹。** 正式资料被判为 unknown 时，优先补足本文件的发布/批准证据，继续保留不确定时复核的行为；不能为追求命中率而无条件放宽 authoritative。

下一轮应先人工查看这些记录，再单独实验权威依据范围和证据失败后的回退策略，其次明确 style_only 与类型边界。生产 Prompt、规则、阈值本轮未修改。
