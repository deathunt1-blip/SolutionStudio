# 文档去重与版本管理（v0.2.2）

## 操作

在「重复资料」选择扫描范围。资料库也提供当前筛选、选中资料及全库入口。扫描只保存建议和规范化指纹，不修改正文、标题、人工分类或权威级别；本版不调用外部模型。

- 完全重复：原文件 SHA-256 一致。新上传默认复用当前可用资料并追加来源；历史库中的独立副本先形成建议。
- 内容重复：可提取正文与表格规范化后相同，仍需确认合并。
- 高度相似：少量文字调整的候选，需要结合差异审阅。
- 疑似版本：同一对象、主要内容相同，日期、版本或关键参数变化。确认时选择当前资料，其他成员变为历史版本。
- 相似资料：不同项目、客户、型号或模板相似。默认保持独立，不自动认定为重复知识。

相同内容组可包含多份资料。近似和版本比较按成对证据展示，不推断相似关系传递。已经属于确认组的资料不能直接参与另一个确认，以免形成主资料链或循环；需先撤销原关系、重新扫描后确认。

所有合并和版本确认都可撤销。资料确认后若再更新版本或改变状态，撤销会返回冲突，保护后续变更。原件、旧版本、来源关系、每次操作审计始终保留。来源列表支持下载每一个来源的原文件；有授权解密副本时也能下载加密备份。

## HTTP 接口

| 方法和路径 | 用途 |
| --- | --- |
| `POST /api/duplicates/scan` | `{documentIds?, source?, filters?}`；返回分类计数、候选数、扫描数和 `truncated` |
| `GET /api/duplicates` | `status`、`relation`、`documentId`、`page`、`pageSize` 筛选建议 |
| `GET /api/duplicates/:id` | 成员、主资料建议、差异、过期状态及可撤销状态 |
| `POST /api/duplicates/:id/merge` | `{canonicalDocumentId}` 确认逻辑合并 |
| `POST /api/duplicates/:id/confirm-version` | `{canonicalDocumentId}` 确认当前版本 |
| `POST /api/duplicates/:id/dismiss` | `{}` 保持独立，不因再次扫描重置决定 |
| `POST /api/duplicates/:id/undo` | `{}` 撤销最近确认 |
| `GET /api/documents/:id/sources` | 主资料及合并成员的全部来源，包括历史来源 |
| `GET /api/documents/:id/sources/:referenceId/original` | 下载某来源的原始文件；`sourceOriginal=1` 下载已保存的加密原件 |

默认 `/api/search` 只返回当前有效主资料。未确认的重复建议也用于检索多样性；版本建议及普通相似建议不折叠。计数和分页均在重复抑制之后计算，`includeDuplicates=1` 可显式查看完整片段结果。历史版本查看使用明确的状态筛选。

## 数据与集成

迁移 `006_document_deduplication.sql` 增加主资料指向、规范化指纹、来源引用、重复建议组、版本组和撤销快照，并回填原有资料当前来源。结构化表格、产品事实和人工确认内容不迁移、不合并。

新来源直接命中当前 SHA-256 时不新增文档、版本、解析任务或模型调用。已归档、历史版本的哈希不作为当前精确匹配目标。飞书资源身份独立于主资料：共享来源中的一个资源变更时建立新资料；移除来源仅在主资料组没有任何有效来源时归档，原文件仍保留。处理中任务不会重新激活已经移出的历史资料。

`DuplicateDetector` 可替换为未来的语义实现。当前算法保留空白分隔、数字单位、型号和表格边界，不把空正文当作重复。候选生成使用有界分桶，遇到保护上限会显示截断，避免把未完整扫描描述成全部比较完成。
